# 二维动画场景制作手册

[技能包入口](../README.md) · [提示词模板](prompts.md) · [坑点记录](pitfalls.md) · [工具配方](tool-recipes.md) · [实际案例](windbell-valley.md)

## 1. 先决定交付目标

| 目标 | 主要交付物 | 播放和声音由谁控制 |
| --- | --- | --- |
| 视频场景展示 | 地图、独立制作素材、最终 MP4、网页 | 预设镜头与时间线，声音混入视频 |
| 实时场景展示 | 地图、独立动画/图集、运行时场景数据 | 场景运行时和实时镜头 |
| 可交互游戏 | 上述实时资源，以及输入、状态、碰撞等现有游戏组件 | 玩家状态、世界位置和游戏时间 |

先查看项目已有技术和素材。用一个背景、一个角色或环境循环完成端到端切片，再扩展。已经有可用渲染器时接入它；工具是否能生成漂亮视频，与游戏是否能正确使用素材分别验收。

风铃溪谷属于第一行。其动画制作流程可以复用，游戏接入仍需在目标项目验证。

## 2. 保存项目简报和素材记录

项目简报至少写清楚：画面风格、地图尺寸/单位、画面视角、可行走区域、主角/NPC、环境动作、目标平台、交付形式、模型/登录选择和当前允许的生成与发布范围。

### 建议目录

```text
project/
  source/                 原图、参考裁剪、原始视频、独立音轨
  prompts/                每次实际提交的提示词
  working/                解码、抠图、遮罩、选出的循环、RIFE 输出
  data/                   素材记录、场景位置、验证报告
  public/                 网页实际需要的媒体、图集和元数据
```

目录名随项目调整；公开包只放需要发布和复用的内容。大量帧文件应排除出日常文本检索。旧产物可恢复归档，保留当前输入、采用输出和关键报告。不要为了整理删除仍被素材描述文件引用的帧。

### 三种数据各自负责什么

| 数据 | 负责内容 |
| --- | --- |
| 动画资产描述 | 帧文件/图集矩形、画布尺寸、每帧时长、局部锚点 |
| 场景数据 | 世界位置、显示比例、图层、相机、显式播放速率 |
| 制作记录 | 参考图、生成报告、模型和登录方式、裁剪、遮罩、来源与验收 |

避免在三个地方重复维护同一个播放时长。原始请求、实际返回和最终采用参数分别记录。

### 坐标约定

- 原地图像素：左上原点，x 向右、y 向下。裁剪框为 `[x0,y0,x1,y1)`，右/下边界不包含；宽高为 `x1-x0`、`y1-y0`。
- 局部像素：裁剪左上角为 `[0,0]`；世界坐标转局部坐标减去裁剪左上位置。
- 角色锚点：在统一画布内选脚底/支撑点，逐帧固定；动态道具和特效不能重新决定它。
- 环境锚点：通常为 `[0,0]`，放置点就是原裁剪左上角；视具体渲染器约定转换。
- 若视频放大到生成分辨率，处理后先还原到参考裁剪尺寸；不要直接把原图遮罩贴到不同尺寸的视频。
- 显示比例为 `s` 时，局部点 `p` 的世界位置为 `位置 + s × (p−锚点)`；环境板、角色和遮挡层必须采用同一坐标变换，再做世界到屏幕转换。

## 3. 制作基础图和动作画布

### 地图

先生成或复用静态地图，保持道路、地平线、建筑尺度、光照和风格。大地图可分区制作，接缝处预留低复杂度过渡；实测接缝后再合并。提前给站位、桥栏、流水和前景遮挡留位置。

### 独立角色和效果

基础图应能看清完整人物和道具，手脚不出画。动作前扩大画布，为挥手、水壶水流、音符和尾巴留空间。需要色键时确认实际像素为均匀纯色；衣服和道具避开该颜色。可先使用已有抠图工具得到透明素材，再合成到真实纯色画布。

### 背景局部动画

从最终采用的地图裁剪参考图，保留足够上下文解释水车、树枝或水流的位置。保存裁剪坐标。图中建筑和草木不是独立洋红精灵，后续应使用局部遮罩。

## 4. 参考图＋详细提示词生成视频

每个动作提示词说明：对象身份、动作顺序、方向和幅度、固定部位、镜头、风格、结束状态。模板见 [prompts.md](prompts.md)。同一张首末参考图有助于闭合端点，但不能保证中间没有变形、暂停或错误运动。

先生成一个易验收动作，再扩展批量。短片长度应覆盖完整动作周期；4 秒或 8 秒是案例选择，不是所有素材的要求。角色动作、背景动画和独立环境声分别保存。

生成前本地检查输入；提交后保留原始视频和调用报告，至少记录提供方、模型、登录模式、实际时长、请求标识、提示词与采用/拒绝原因。视频可用与视觉质量达标分别判断。

## 5. 抠像、遮罩和前景遮挡

### 角色色键路线

用现有 `video-frames` 去色键并检查透明边缘。对溢色先使用工具的参考图与去污染选项。`full` 溢色处理是针对具体素材的修正，不应无条件用于含真实紫色的角色。检查发丝、手指、衣边、淡色水滴和音符是否被误删。

### 背景遮罩路线

遮罩是与原裁剪同尺寸的灰度图：白色取动画，黑色取原图，灰色按比例融合。

```text
最终裁剪 = 动画帧 × 遮罩 + 原裁剪 × (1 − 遮罩)
```

处理步骤：

1. 标出水面、轮体或叶簇的可动区域，保留整个动作幅度所需范围。
2. 留出适量羽化边缘；固定轴心支撑、石块、树干和粗枝另做零值保护区。
3. 必要时根据固定区域匹配生成视频与原图的色调/曝光；先确认固定区域确实可用于估计，不能对所有素材机械套用。
4. 使用同一遮罩处理整个循环；RIFE 后再次恢复这张遮罩。
5. 合回原图，逐帧核验遮罩为零的区域与原图相同；重点保护 ROI 要完全位于零值区。
6. 观看边缘，检查羽化处是否重影、漏出静态轮辐或切断水流。

### 站位与遮挡

脚底位置落在正确支撑面，再处理遮挡。站在桥上的人物可能需要近侧石栏盖住脚部；只移动人物坐标不能表达所有前后关系。固定支撑和前景石块也可从原图提取为遮挡层。图层顺序按画面和运行时判断，不能直接套旧项目的 z 值。

## 6. 先选循环，再补帧

先观看源视频，检查动作真实、方向、结构、画布边界及各相位。再由既有工具选择完整周期、去除重复闭合帧，保存选帧和时间记录。走路/跑步还需要看脚底接触、步态周期与移动速度，不能用 NPC 待机周期规则直接代替。

### 时间必须保持

```text
96 帧 ÷ 24 fps = 4 秒
补成 192 帧：192 帧 ÷ 4 秒 = 48 fps
每帧时长 = 4 ÷ 192 秒 ≈ 20.833 毫秒
```

若补成 192 帧后仍以 24 fps 播放，动作会变成 8 秒。最终视频帧率和素材帧率可以不同，由实际时间采样。

对于等时长源帧，可以使用包内 RIFE 辅助脚本；不等时长帧需要按时间处理，脚本会拒绝直接按帧数重采样。保留引擎 `between="auto"` 的质量保护：被拒绝的提案不会作为有效 RIFE 新帧采用，具体替代和采样由引擎决定并写入报告，输出帧总数不等于有效插帧数量。

### 循环验收

- 观看至少多个完整周期及最后一帧→第一帧，关注停顿、跳变、反转和淡出重新出现。
- 检查接触表的分布相位，也观看连续播放；仅首尾相似不能证明完整动作可用。
- 接缝差异可与普通相邻帧差异比较，但不替代目视检查，也不把案例 MAE 当通用阈值。
- 源动作错误先修正源动作；补帧错误用引擎质量保护、其他已有选项或不同素材处理。
- 精确转速需跟踪可识别的轮辐/标记并测量实际转角。提示词写了“一圈”不等于实测一圈。

## 7. 合成展示或接入游戏

### 预渲染展示

用动画资产元数据驱动各自周期，场景数据控制位置、缩放、遮挡和镜头。渲染到新输出目录，完成解码与画面检查后，再与声音合并并替换公开成品。镜头从左走到右的游览有不同起终点，不能称为整体世界无缝循环。

### 游戏/实时展示接入

1. 复用现有引擎的动画和渲染组件。源帧可打包成图集或适合当前平台的其他资源，并保留帧矩形、原画布尺寸、裁剪偏移、锚点和时长。
2. 根据目标设备的实际纹理上限拆分图集；不要把几百张高分辨率帧硬塞进一张横条。评估解码内存、加载时间和可见区域，不凭帧数估计资源成本。
3. 按经过时间选帧。等帧时长循环可用：

   ```js
   const phase = elapsedSeconds % cycleSeconds;
   const frameIndex = Math.min(frameCount - 1,
     Math.floor(phase * frameCount / cycleSeconds));
   ```

   不等时长帧按累计时长选择；不用每次渲染固定加一帧。保留项目已有的暂停/恢复与计时规则。
4. 地图、环境循环、玩家和遮挡层使用同一世界坐标与相机变换。玩家移动独立于动画帧率，状态切换使用已有状态机。
5. 先接入一个环境循环，验证角色移动、镜头滚动、遮挡和低帧率播放，再加入其他效果。

这部分是接入指导。仅导出 PNG 或观看 MP4 不能宣称游戏运行时已验收。

## 8. 音乐与环境声

音乐、风声、流水和机械声分轨保存，注明原创、本地合成、生成音频或录音来源。原案例的环境音为生成的自然录音风格，不能称为现场实录。

短环境声循环可用交叉淡化，检查接缝、响度和峰值。音乐渲染器随平台选择，macOS 声库是案例方案。确认使用的音源可用于该项目交付。

- 展示：由镜头/主角预设位置计算声源距离与声场，离线混入视频。
- 游戏：根据玩家或项目定义的听者当前位置平滑调整距离衰减和声场；玩家停住、折返、传送后均应正确。延续现有音频组件，在用户手势允许后启动声音。

声源的作用半径、响度和淡化方式按实际试听决定，不把案例的时间点或 dB 数字复制为默认。

## 9. 发布和交付

公开包使用相对路径，核对仓库子路径部署。视频页面检查自动静音播放、声音开关、跳转、资源加载与 HTTP Range。音频和视频采用适合目标平台的格式，完整解码和实际浏览器播放均有证据。

发布前检查：采用产物、来源与许可、敏感字段、私人绝对路径、旧失败文件、工作帧。已有发布文件先备份；生成、付费模式与对外发布遵循当前项目授权，不由技能自动赋予。

### 最小验收清单

| 阶段 | 可观察的通过标准 |
| --- | --- |
| 源动作 | 要求的动作确实发生；手脚、道具、轮辐等没有影响使用的变形 |
| 循环 | 连续多轮观看，无不可接受的跳变、暂停、反转；保存切循环证据 |
| 空间 | 尺寸和锚点稳定，站位正确，相机移动时素材与背景一致 |
| 遮罩 | 零值区与固定 ROI 逐帧相同，边缘与前景遮挡经过观看 |
| 补帧 | 实际输出时长不变，帧总数/有效 RIFE 数如实记录 |
| 声音 | 时长正确、无削波、循环自然、位置变化可听辨 |
| 展示 | 全片解码、真实浏览器播放和跳转正常，线上采用版本可核对 |
| 游戏 | 输入、移动、状态、相机、计时、资源加载和位置音效在目标运行时验证 |

完成后保留一份项目复盘：哪些参数可复用、哪些重新标定、遇到什么失败、最终如何验证。下一项目从这一页找到证据，而无需重读整段聊天。
