# 实际坑点与处理方式

[手册](handbook.md) · [实际案例](windbell-valley.md)

以下“实际发生”来自风铃溪谷记录。“接入注意”是对未来项目的约束和验证建议，不表示当时已完成游戏接入。

## 实际发生的错误与返工

| 症状 | 原因或定位 | 处理 | 修正后检查 |
| --- | --- | --- | --- |
| 老人看起来站在桥拱外侧 | 脚底站位和前后遮挡都不正确 | 按桥面改站位，提取近侧石栏覆盖人物下部 | 桥面特写、脚底及栏杆层级 |
| 三个 NPC 没有动作 | 原方案只使用静态人物 | 各自生成完整动作：挥手、倾壶、吹笛摇头 | 连续播放，确认动作和道具真实变化 |
| `video-canvas` 拒绝“纯洋红”图 | 四角实际为不同的近洋红像素 | 先抠出人物，再合成到真正纯色画布，增加留白 | 像素与画布检查通过后才提交视频 |
| 画布准备失败后仍启动视频命令 | 下游依赖的 `canvas.png` 没有生成 | 依赖步骤串行，先验证输入文件再提交 | 本地预处理错误不算提供方生成失败 |
| 第一版三角旗翻到绳子上方 | 动作方向/挂点约束不充分 | 第二版强调挂点不动、旗面始终垂在绳下 | 多个中间相位与连续循环 |
| 第一版柳树动作过于微弱 | 源视频摆动幅度不足 | 调整枝梢幅度后采用第二版 | 确认枝梢可见变化，主干仍固定 |
| 炊烟透明边缘有紫色残留 | 自动溢色处理对该烟雾素材不足 | 使用工具的完整溢色处理与参考调色板 | 在实际天空和屋顶上检查边缘；不作为所有角色默认 |
| 水车轴心边界仍出现变化 | 固定保护区覆盖不完整，羽化附近漏出动画 | 扩大支撑与前景石块的零值排除区，重做遮罩和补帧产物 | 指定轴心、石块 ROI 在所有输出帧与原图相同 |
| 网页跳转后回到开头 | 本地静态服务未正确支持视频字节范围读取 | 换用支持 Range 的服务 | 实际跳转，响应 `206` 与 `Content-Range` |
| 同时提交三个环境声请求出现限流 | 当时提供方限制为每秒两次提交 | 错开提交，失败任务单独重提 | 保留报告，按当前服务限制调整；不固定永久限流值 |
| 水车首次提交网络超时 | 客户端没得到结果，服务端是否接收不确定 | 如实记录，后续明确进行一次手动重提 | 区分网络问题和画面质量，不隐藏重复请求 |
| 帧目录拖慢检索 | 原始、失败与已采用素材混在活跃目录 | 可恢复归档未采用文件，排除大量帧的文本检索 | 当前描述文件引用的产物仍可读取，归档可找回 |

## 已观察到的质量边界

- 部分人物和昆虫的 RIFE 中间帧被引擎质量保护拒绝。输出总帧数不能当作“所有提案都成功”的证明。
- 源视频中的错误动作不靠补帧解决；RIFE 的主要作用是增加有效采样、改善连续性。
- 水车提示词要求精确一圈，但验收只确认了可见转动和结构/遮挡检查；没有测量精确一圈或转速。
- 原始视频、抠像、遮罩、插帧、程序落叶和混音分别贡献结果。不能把整个成品归因于某一个生成模型。

## 新项目接入注意

| 容易误用的做法 | 应采取的做法 |
| --- | --- |
| 复制旧地图坐标、裁剪框和遮罩 | 根据新地图重新标定；旧数据仅作为字段与方法参考 |
| 按整个人物及特效外接框定位脚底 | 从人体支撑点确定固定锚点，水滴/音符留在同一画布 |
| 用人物色键流程处理河流裁剪 | 完整背景使用局部遮罩，固定部分仍取原图 |
| 只检查首尾相同 | 检查动作各相位、连续多轮及末→首衔接 |
| RIFE 增加帧数后沿用旧 fps | 用原时长除以输出帧数计算每帧时长 |
| 每次渲染固定推进一帧 | 按项目经过时间选择帧；变帧时长按累计时间采样 |
| 大量帧直接组成超长单张图集 | 核对设备纹理上限、资源内存与加载方式，按引擎拆分 |
| 图集裁剪后丢弃原画布和偏移 | 保留未裁剪尺寸、局部偏移与锚点，防止跳动 |
| 沿用影片中的音效出现时间 | 游戏使用当前听者世界位置，验证停留和折返 |
| 预览视频可播放就算游戏完成 | 在目标运行时检查输入、相机、遮挡、计时与加载 |
| 把一次游览称为世界无缝循环 | 分别说明局部素材循环和整片起终点的实际关系 |

## 如何记录下一次失败

```text
对象与采用版本：
预期动作：
实际症状（附帧/截图/时间）：
输入文件及报告摘要：
失败阶段：预处理 / 请求 / 源动作 / 抠像 / 循环 / RIFE / 合成 / 运行时 / 发布
定位依据：
尝试的修正和产生的新输出目录：
修正后的可观察检查：
是否适用于其他项目、有哪些条件：
```

同一故障重复出现且有证据时，再将修正升级为可复用流程。不要把每次尝试都变成强制配置。
